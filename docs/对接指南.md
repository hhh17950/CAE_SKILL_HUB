# 对接指南

当前公开一个 guie2 测试流程。调用方先确保模型位于服务端可读的共享根目录，提交参数并保存 `run_id`，随后查询状态和日志。所有业务接口使用 `Authorization: Bearer <token>`；不同身份不能读取彼此的任务。

浏览器调试入口是 `/docs`，Swagger UI 已本地化，无需连接 CDN；`/openapi.json` 提供机器可读契约，`/redoc` 不再提供。容器部署时输入路径填写 API 与 Worker 都能访问的容器内路径，例如模型 `/models/part.stp` 和已有工程 `/app/workspace/existing-project`，不是宿主机文件路径。

| 操作 | 接口 | 输出 |
| --- | --- | --- |
| 服务探测 | `GET /healthz` | API 存活信息 |
| 提交任务 | `POST /api/v1/guie-runs` | HTTP 202、`run_id`、查询与日志地址 |
| 查询任务 | `GET /api/v1/guie-runs/{run_id}` | 状态、退出码、时间、错误 |
| 读取结果 | `GET /api/v1/guie-runs/{run_id}/results` | 云图信息 JSON，脚本退出码为 0 后可读 |
| 读取日志 | `GET /api/v1/guie-runs/{run_id}/logs/{kind}` | `kind` 为 `stdout`、`stderr` 或 `jusmar` |

提交示例：

```json
{
  "model_path": "/模型共享目录/part.stp",
  "project_dir": "/工程共享目录/existing-project",
  "jusmar_log_path": "/输出共享目录/solver.log",
  "cloud_info_path": "/输出共享目录/result.json",
  "young_modulus": 200000000000.0,
  "poisson_ratio": 0.3,
  "density": 7850,
  "number_of_roots": 10
}
```

`model_path`、`project_dir` 是必填的服务端绝对路径，分别位于 `CAE_MODEL_ROOT`、`CAE_PROJECT_ROOT` 下。`project_dir` 必须是已存在的工程目录，服务不会为该参数新建目录。`jusmar_log_path`、`cloud_info_path` 可选；传入时使用该路径，未传入时使用任务默认路径。自定义输出必须是 `CAE_OUTPUT_ROOT` 下尚不存在的文件，父目录必须已存在，云图路径以 `.json` 结尾。若重用已经存在的文件，接口返回 422，避免覆盖旧任务结果。`young_modulus` 和 `poisson_ratio` 为浮点数，`density` 和 `number_of_roots` 为整数；数值单位与真实 CAE 语义须与脚本提供方核定。

两个自定义输出路径不能指向同一文件，也不能复用其他任务已经占用的路径；即使前一个任务尚未开始，重复提交也会返回 422。项目目录可以被多次引用，脚本是否允许并发或重复修改同一工程须由流程提供方确认。

中台生成以下脚本环境变量：

| 环境变量 | 来源 |
| --- | --- |
| `GUIE_MODEL_PATH` | 校验后的 `model_path` |
| `GUIE_YOUNG_MODULUS` | `young_modulus` |
| `GUIE_POISSON_TATID` | `poisson_ratio`；保持脚本现有拼写 |
| `GUIE_DENSITY` | `density` |
| `GUIE_NUMBER_OF_ROOTS` | `number_of_roots` |
| `GUIE_PROJECT_DIR` | 必填的 `project_dir`，已有工程目录 |
| `GUIE_JUSMAR_LOG` | 可选的 `jusmar_log_path`；未传时为 `static/logs/<run_id>/jusmar.log` |
| `GUIE_CLOUD_INFO_DIR` | 可选的 `cloud_info_path`；未传时为 `workspace/runs/<run_id>/cloud_info.json` |

`succeeded` 仅表示脚本退出码为 0；脚本返回非 0 则为 `failed`。测试脚本的 `cloud_info.json` 只包含参数回显和 `test_only=true`，不是模态计算结果。当前没有 MCP 接口；甲方可先通过 HTTP 接入。

## 从提交到取结果

1. 与部署方确认服务地址、Bearer token，以及模型在服务端的路径。当前没有文件上传接口。
2. 提交上述 JSON，收到 HTTP 202 后保存响应中的 `run_id` 和 `status_url`。每次 POST 都是新任务，不自动去重；网络超时后不要直接无限重试。
3. 每隔约 1～2 秒 GET `status_url`。`queued` 为排队，`running` 为执行中。
4. 当状态为 `succeeded` 时 GET `result_url`；任务正常退出但没有生成结果文件时，该接口仍会返回 404。
5. `failed`、`timed_out`、`unknown` 都应停止轮询，读取日志并按错误排查。`unknown` 要人工核对，不自动重跑。

提交响应形状如下（示例 ID 和时间仅用于说明）：

```json
{
  "run_id": "run_example",
  "status": "queued",
  "created_at": "2026-09-21T00:00:00Z",
  "started_at": null,
  "finished_at": null,
  "exit_code": null,
  "error": null,
  "status_url": "/api/v1/guie-runs/run_example",
  "result_url": "/api/v1/guie-runs/run_example/results",
  "log_urls": {
    "stdout": "/api/v1/guie-runs/run_example/logs/stdout",
    "stderr": "/api/v1/guie-runs/run_example/logs/stderr",
    "jusmar": "/api/v1/guie-runs/run_example/logs/jusmar"
  }
}
```

查询接口返回同一结构，结束后填入 `finished_at`、`exit_code` 和必要的 `error`。时间为 UTC；响应 URL 是相对于服务地址的路径。

结果接口返回 `{"run_id": "...", "exit_code": 0, "cloud_info": {...}}`。`cloud_info` 当前为测试参数回显；真实脚本的结果格式需另行确认，不能当作稳定的 CAE 后处理数据模型。

错误采用 `application/problem+json`，包含 `code`、`detail`、`request_id` 和字段错误 `errors`。401 表示认证失败，404 表示不存在或无权访问，409 表示结果未就绪，422 表示输入不符合约定，413 表示请求过大，500 表示服务或结果格式异常。日志接口返回纯文本；任务尚未启动时，日志可能尚不存在。

当前数值约束：`young_modulus > 0`、`-1 < poisson_ratio < 0.5`、`density > 0`、`number_of_roots >= 1`，禁止额外字段和非有限数值。6 个业务输入为必填，其中 `project_dir` 指向已有工程；2 个输出路径为可选。任务的 stdout/stderr 日志仍由服务按 `run_id` 保存。
