# 对接指南

当前公开一个 guie2 测试流程（结构模态分析）：调用方上传几何模型文件并提交物理参数，服务返回 `run_id`，随后查询状态、结果和日志。模型文件由调用方上传，服务端不接受调用方指定的服务端文件路径。

浏览器调试入口是 `/docs`，Swagger UI 已本地化，无需连接 CDN；`/openapi.json` 提供机器可读契约，`/redoc` 不再提供。契约由 `python -m scripts.export_openapi` 从当前代码生成，接口行为以契约为准。

服务自身不做身份认证，也不按调用方隔离任务：任何能访问服务地址的调用方都能读取任意 `run_id` 的状态、结果和日志。需要访问控制时，在部署层用反向代理或网络策略实现。

| 操作 | 接口 | 输出 |
| --- | --- | --- |
| 服务探测 | `GET /healthz` | API 存活信息 |
| 提交任务 | `POST /api/v1/guie-runs/modal` | HTTP 202、`run_id`、查询与日志地址 |
| 查询任务 | `GET /api/v1/guie-runs/{run_id}` | 状态、退出码、时间、错误 |
| 读取结果 | `GET /api/v1/guie-runs/{run_id}/results` | 云图信息 JSON，脚本退出码为 0 后可读 |
| 读取日志 | `GET /api/v1/guie-runs/{run_id}/logs/{kind}` | `kind` 为 `stdout`、`stderr` 或 `jusmar` 的纯文本日志 |
| 下载云图 | `GET /api/v1/guie-runs/{run_id}/cloud/{filename}` | 该任务 `cloud_info.json` 中声明的云图 PNG |

## 提交任务

提交使用 `multipart/form-data`，几何模型作为文件字段上传：

```bash
curl -sS -D- -X POST http://127.0.0.1:8000/api/v1/guie-runs/modal \
  -F "model_file=@part.stp" \
  -F "young_modulus=2.0e11" \
  -F "poisson_ratio=0.3" \
  -F "density=7850" \
  -F "number_of_roots=10"
```

| 字段 | 形式 | 必填 | 约束 |
| --- | --- | --- | --- |
| model_file | 文件 | 是 | 几何模型内容，不能为空，且不超过 `CAE_MAX_MODEL_BYTES`；文件名取上传文件名 |
| young_modulus | 表单 | 否 | 大于 0，默认 2e11 |
| poisson_ratio | 表单 | 否 | 大于 -1 且小于 0.5，默认 0.3 |
| density | 表单 | 否 | 整数，大于 0，默认 7850 |
| number_of_roots | 表单 | 否 | 整数，大于等于 1，默认 10 |

字段名使用 `poisson_ratio`；服务把它映射成脚本环境变量 `GUIE_POISSON_TATIO`（脚本现有拼写，见下表）。上传的几何模型按字节原样保存，服务不解析几何语义。

提交响应形状如下（示例 ID 和时间仅用于说明），同时带 `Location` 头指向状态地址：

```json
{
  "run_id": "run_example",
  "status": "queued",
  "created_at": "2026-09-21T00:00:00Z",
  "started_at": null,
  "finished_at": null,
  "exit_code": null,
  "error": null,
  "status_url": "/api/v1/guie-runs/run_example",
  "result_url": "/api/v1/guie-runs/run_example/results",
  "log_urls": {
    "stdout": "/api/v1/guie-runs/run_example/logs/stdout",
    "stderr": "/api/v1/guie-runs/run_example/logs/stderr",
    "jusmar": "/api/v1/guie-runs/run_example/logs/jusmar"
  }
}
```

每次 POST 都创建新任务，不做幂等去重；网络超时后不要直接无限重试。

## 任务目录与输出路径

所有输出由服务在 `CAE_WORKSPACE_ROOT`（默认 `workspace`）下按 `run_id` 生成，调用方不能指定路径：

| 内容 | 位置 |
| --- | --- |
| 上传的几何模型 | `<workspace>/<run_id>/model/<上传文件名>` |
| 工程目录 | `<workspace>/<run_id>/project`，由服务创建 |
| 任务 stdout / stderr | `<workspace>/<run_id>/logs/stdout.log`、`logs/stderr.log` |
| 求解器日志 | `<workspace>/<run_id>/jusmar.log` |
| 云图信息 | `<workspace>/<run_id>/cloud_info.json` |
| 云图 PNG | `cloud_info.json` 中每条 `cloud_file_name` 指向的路径 |

服务启动脚本时生成以下环境变量：

| 环境变量 | 来源 |
| --- | --- |
| `GUIE_MODEL_PATH` | 上传文件保存后的绝对路径 |
| `GUIE_YOUNG_MODULUS` | `young_modulus` |
| `GUIE_POISSON_TATIO` | `poisson_ratio`；保持脚本现有拼写 |
| `GUIE_DENSITY` | `density` |
| `GUIE_NUMBER_OF_ROOTS` | `number_of_roots` |
| `GUIE_PROJECT_DIR` | 任务的 `project` 目录 |
| `GUIE_JUSMAR_LOG` | 任务的 `jusmar.log` |
| `GUIE_CLOUD_INFO_DIR` | 任务的 `cloud_info.json` |

另外仍会导出 `GUIE_TEST_SLEEP_SECONDS` 和 `GUIE_TEST_EXIT_CODE`（来自 `CAE_TEST_SLEEP_SECONDS`、`CAE_TEST_EXIT_CODE`）。当前受控脚本不读取这两个变量，它们只保留给旧的测试脚本，不要依赖。

## 状态与轮询

状态为 `queued`、`running`、`succeeded`、`failed`、`timed_out`、`unknown`。查询接口返回与提交响应相同的结构，结束后填入 `finished_at`、`exit_code` 和必要的 `error`。时间为 UTC；响应 URL 是相对于服务地址的路径。

1. 提交后保存响应中的 `run_id` 和 `status_url`。
2. 每隔约 1～2 秒 GET `status_url`。`queued` 为排队，`running` 为执行中。
3. 状态为 `succeeded` 时 GET `result_url`；任务正常退出但没有生成结果文件时，该接口仍返回 404。
4. `failed`、`timed_out`、`unknown` 都应停止轮询，读取日志并按错误排查。`unknown` 要人工核对，不自动重跑。

任务也可能在子进程启动前就失败（启动器缺失或不可执行、脚本被删、工作目录不可用）：此时 `exit_code` 保持 `null`，`error` 会带上完整启动命令与操作系统原因，同一句话也会追加到该任务的 `stderr` 日志，可直接用日志接口读到，不必去翻 Worker 服务日志。

`succeeded` 只表示脚本退出码为 0，不保证物理结果正确或云图文件存在。当前受控脚本在 `finally` 中固定以 0 退出，因此退出码 0 更不能当作流程成功的证明；请把 `cloud_info.json` 是否生成、`result_url` 是否可读作为辅助判据。

## 结果与云图

结果接口返回 `{"run_id": "...", "exit_code": 0, "cloud_dir": "...", "cloud_info": {...}}`。`cloud_info` 是按模态阶数编号的字典，每条包含 `vtk_file`（服务器本地 VTK 文件）、`cloud_file_name`（服务器本地 PNG 路径）和 `frequency`（该模态频率）。

`cloud_dir` 与 `cloud_file_name` 是服务器本地路径，调用方不能直接访问；请用云图下载接口，按 `cloud_file_name` 的文件名部分取图：

```bash
curl -sS -o cloud_3d_1.png \
  http://127.0.0.1:8000/api/v1/guie-runs/run_example/cloud/cloud_3d_1.png
```

该接口只返回当前任务 `cloud_info.json` 中真实声明的文件名，其他文件名一律 404，因此不能用来遍历服务器文件。

## MCP 接口

同一个服务在 `/mcp` 上提供 MCP（Streamable HTTP）端点，供智能体直接调用，无需手写 HTTP 轮询。服务名称为“茉莉平台CAE仿真”，与 REST 接口共用同一数据库、任务目录和 Worker，任务可在两种接口之间混用。

可用工具：

| 工具 | 标题 | 读写 | 用途 |
| --- | --- | --- | --- |
| submit_modal_run | 提交结构模态仿真任务 | 写 | 以 Base64 内容提交任务，返回 `run_id` 和状态地址 |
| get_run_status | 查询任务状态 | 只读 | 轮询任务状态、退出码和错误 |
| get_run_result | 读取云图结果 | 只读 | 任务成功后读取 `cloud_info`，并为每条结果补充可直接下载的 `image_url` |
| get_run_log | 读取任务日志 | 只读 | 读取 stdout、stderr 或 jusmar 日志 |

### 智能体怎么用（意图 → 调用）

服务在 `initialize` 的 `instructions` 字段给出全局用法说明，每个工具另带标题、中文说明与 `readOnlyHint` 标注（`submit_modal_run` 为写操作，其余三个只读）。一句“用茉莉平台帮我仿真这个几何模型并返回云图”对应的调用链是：

1. `submit_modal_run` → 得到 `run_id`；
2. `get_run_status` 轮询，直到 `succeeded`（或 `failed` / `timed_out` / `unknown`）；
3. `get_run_result` → 每个模态的 `frequency` 与云图 `image_url`，`GET` 该 URL 即得 PNG；
4. 失败时 `get_run_log` 读日志定位原因。

模型文件与参数缺失时的约定（已写进 `instructions` 与 `submit_modal_run` 的说明，供智能体遵守）：

- 几何模型文件**必填**、且只能来自用户：工具接收 Base64 内容（`model_b64`）与文件名（`model_filename`），不接受文件路径。用户没有给文件时，智能体应先向用户索取（请其上传文件或给出可读取的路径），不得自行编造几何体、也不得用示例文件冒充用户模型。
- 物理参数可省略：`young_modulus`（2.0e11）、`poisson_ratio`（0.3）、`density`（7850）、`number_of_roots`（10）均有默认值，省略即按钢计算；此时智能体应在回复中说明“使用的是默认参数”，而不是把它说成用户提供的值。
- 工具失败时返回带原因的 `isError` 结果（如“run_id 不存在”“任务状态为 failed，尚未成功”），智能体据此自纠或改走 `get_run_log`。

相关配置：

- `CAE_MCP_ENABLED`：默认 `true`；设为 `false` 时不挂载 `/mcp`。缺少 MCP 依赖时服务会记录错误并跳过挂载，REST 接口不受影响。
- `CAE_PUBLIC_BASE_URL`：用于把服务器本地图片路径拼成调用方可访问的 URL；MCP 结果里的 `image_url` 基于它生成，请填部署后调用方能访问到的地址。

`/mcp` 不做 Host 校验：内网自用、服务自身无鉴权（访问控制由部署层负责），因此不存在"地址不在白名单就 421"的问题，智能体用 IP、域名或反向代理地址访问都可以。

通过 MCP 提交的模型内容以 Base64 传输，受 `CAE_MAX_MODEL_BYTES` 限制；超过限制请改用上文的 multipart 上传。MCP 传输层自身的请求体上限与 `CAE_MAX_REQUEST_BYTES` 保持一致，同样由该配置项控制。

## 错误与限制

错误采用 `application/problem+json`，包含 `code`、`detail`、`request_id` 和字段错误 `errors`。404 表示任务或文件不存在，409 表示结果尚未就绪，413 表示请求或上传内容过大，422 表示输入不符合约定，500 表示服务或结果格式异常。401 可能来自部署层的反向代理认证，不是本服务产生。日志接口返回纯文本；任务尚未启动时，日志可能不存在。

默认限制：请求体上限 `CAE_MAX_REQUEST_BYTES`（100 MiB），上传几何模型上限 `CAE_MAX_MODEL_BYTES`（50 MiB），单任务执行超时 `CAE_RUN_TIMEOUT_SECONDS`（300 秒）。数值单位与真实 CAE 语义须与脚本提供方核定；本服务只按退出码和文件存在性判断结果，不校验物理正确性。
