# 对接指南

面向两类对接方：合作方 Agent / HTTP 客户端，以及负责接入真实 GUI Runner 与 `jusmar_app` 的内部团队。当前 REST 接口可联调；真实 GUI 和 MCP 均未接入。

## 1. 合作方 Agent 对接流程

```text
读取工作流目录 → 上传几何资产 → 生成类型化请求 → 预检
→ 带幂等键提交 → 查询 run 状态 → 获取结果 → 下载文件
```

Agent 负责把用户要求转换为公开 Schema，并在缺少材料参数、单位或业务条件时追问用户。Agent 不能传 Python 代码、SDK 方法名、`project_id`、本机绝对路径或任意 GUI 命令。

### 身份与公共约定

所有业务接口使用 `Authorization: Bearer <token>`。相同调用身份才可读取自己的资产、运行和结果；跨身份访问统一返回 404。JSON 请求拒绝未知字段、非法枚举、数字字符串和布尔整数。

`POST /analysis-runs` 必须带 `Idempotency-Key`，长度 1–160，允许字母、数字、`.`、`_`、`:`、`-`。同身份、同键、同规范化请求返回同一 `run_id`；同键不同请求返回 409。网络超时后应使用原键重试或查询原任务，不应立即新建任务。

错误返回 `application/problem+json`，字段包含 `status`、`code`、`detail`、`request_id` 和可选 `errors`。运行执行失败时，查询接口本身仍返回 HTTP 200，必须同时判断 `data.status`。

### 接口顺序与输入输出

| 步骤 | 接口 | 关键输入 | 关键输出 | Agent 行为 |
| --- | --- | --- | --- | --- |
| 服务探测 | `GET /healthz` | 无 | `status`、`execution_mode` | 只代表 API 存活，不代表 Worker / CAE 就绪 |
| 能力发现 | `GET /api/v1/workflows` | 无 | 工作流、版本、Schema、限制、步骤 | 选择受支持的类型和版本 |
| 流程详情 | `GET /api/v1/workflows/{workflow_id}/versions/{version}` | 流程 ID、版本 | 单一流程的 Schema、限制、步骤 | 缓存或展示选定流程的定义 |
| 上传资产 | `POST /api/v1/assets` | `multipart file` | `asset_id`、SHA-256、格式 | 保存 `asset_id`，不要传本地路径 |
| 查询资产 | `GET /api/v1/assets/{asset_id}` | `asset_id` | 资产元数据 | 按需确认资产仍可见 |
| 预检 | `POST /api/v1/analysis-validations` | 完整分析 JSON | `valid`、检查项、规范化请求 | `valid=false` 时修正或追问 |
| 提交 | `POST /api/v1/analysis-runs` | 完整分析 JSON、幂等键 | HTTP 202、`run_id`、`status_url` | 持久保存运行 ID 和幂等键 |
| 查询 | `GET /api/v1/analysis-runs/{run_id}` | `run_id` | 状态、当前步骤、错误或结果 | 退避轮询，不重新提交 |
| 取消 | `POST /api/v1/analysis-runs/{run_id}/cancel` | `run_id` | `cancelled` 或 `cancelling` 状态 | 继续查询直到终态 |
| 结果 | `GET /api/v1/analysis-runs/{run_id}/results` | `run_id` | 结果摘要和文件清单 | 仅在 `succeeded` 时调用 |
| 文件 | `GET /api/v1/analysis-runs/{run_id}/artifacts/{artifact_id}` | `run_id`、文件 ID | 原始文件 | 按结果中的 SHA-256 校验 |

排队任务取消通常立即为 `cancelled`；运行中先为 `cancelling`，需要继续查询确认。

### 当前模态分析请求

`modal_analysis@1.0` 当前只允许自由边界、一个各向同性线弹性材料和全部实体统一赋材：

```json
{
  "workflow_id": "modal_analysis",
  "workflow_version": "1.0",
  "input": {
    "geometry": {
      "geometry_asset_id": "asset_replace_me",
      "length_unit": "mm"
    },
    "material": {
      "material_name": "示例钢材",
      "young_modulus_pa": 200000000000,
      "poisson_ratio": 0.3,
      "density_kg_m3": 7850,
      "constitutive_model": "linear_elastic_isotropic",
      "assignment": "all_solids"
    },
    "mesh": {
      "mesh_type": "tetrahedron",
      "element_order": "first_order",
      "mesh_density": "medium"
    },
    "boundary_condition": "free",
    "eigen_method": "lanczos",
    "mode_count": 10,
    "process_count": 1
  }
}
```

支持后缀为 `.stp`、`.step`、`.igs`、`.iges`、`.x_t`，默认文件上限 10 MiB。上传成功不表示 CAD 有效；`valid=true` 也不表示 CAD、网格或物理求解已验证。

预检中 `passed` 是已完成的提交阶段检查，`deferred` 是仅能在 Worker 或真实 CAE 环境中确认的条件。当前 Agent 应将 `length_unit`、材料物性、边界语义理解为用户必须表达的业务信息，不能从文件名或 SDK 默认值猜测。

### 状态与结果语义

`queued`、`running`、`cancelling` 是进行中状态；`succeeded`、`failed`、`cancelled`、`timed_out`、`unknown` 是终态。`unknown` 表示外部执行无法确认，调用方不能自动重放，应保留 `run_id` 交由运维核对。

当前结果含 `synthetic=true`、`quality_status=not_evaluated` 及 `result_type=modal_mock_summary`。它不含真实频率、位移、应力或反力；合作方不能把此结果表述为真实仿真结论。

HTTP 202 仅代表请求已接受和持久化，具体语义可参考 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-202-accepted)。接口完整 Schema 由 [OpenAPI 合同](./contracts/openapi.json) 提供。

## 2. 真实 GUI Runner 与 SDK 对接

现有业务描述表明传统脚本通过类似 `guierunner --entry xxxx.py` 的方式启动。这不表示使用某个特定第三方工具，也不能据此假定具体参数、解释器或运行模式。

当前 Mock Worker 启动固定 Python 模块，通过独立目录交换 `input.json`、`progress.json`、`result.json`、日志、暂存几何和结果文件。真实接入应保留这一受控边界：Worker 固定配置真实 Runner 与入口脚本，脚本读取版本化输入并输出版本化回执。Agent 永远不能指定入口文件或命令。

真实 Runner 的 Python 可能无法导入 FastAPI、Pydantic 或整个项目。此时实现最小桥接脚本，使用已验证的 JSON 文件协议；桥接脚本与业务 Adapter 必须共用同一套字段与单位语义。

### 真实 SDK 映射核对表

| 客户业务语义 | 当前 Mock 处理 | 真实接入必须验证 |
| --- | --- | --- |
| `geometry_asset_id` | Worker 复制并核对文件 | GUI / SDK 能否导入，格式和完成信号 |
| `length_unit` | 仅保留快照 | SDK 单位、缩放和导入单位策略 |
| `mesh_density` | 映射低/中/高模拟值 | 实际尺寸规则与可重复性 |
| 杨氏模量 Pa、密度 kg/m³ | 原数值传给 Mock | SDK 单位或显式转换 |
| `assignment=all_solids` | 模拟创建属性 | 实体选择与真正赋材确认 |
| `boundary_condition=free` | 无约束工况 | GUI 默认边界与刚体模态语义 |
| `mode_count` | 模拟工况设置 | 是否包含刚体模态及返回阶数 |
| `process_count` | 模拟提交参数 | CPU、许可证与求解器并行含义 |

SDK 字段改名、参数结构变化或调用需要拆分，通常修改 Adapter / 工作流即可。若真实需求变为“压力加载到指定面”或“多材料局部赋材”，则用户必须表达新的业务语义，需要设计并发布新的 Schema 或工作流版本。

### 真实接入验收条件

1. 提供一条已验证的传统脚本、准确 Runner 命令和运行环境说明。
2. 确认参数传入与结构化成功 / 失败结果回传方式。
3. 记录每个 SDK 方法的实际签名、返回、异常、副作用和可查询标识。
4. 验证单位、赋材范围、边界条件和模态阶数在真实工程中的含义。
5. 验证提交求解后的状态查询、最终结果导出和 Runner 退出策略。
6. 演练 Runner、GUI、求解器崩溃、取消、超时和主机重启后的状态核对。

未完成上述验证前，真实模式应保持拒绝启动，不能因为 Mock 流程通过就对外宣称真实 CAE 可用。
