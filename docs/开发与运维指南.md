# 开发与运维指南

本指南面向后端、CAE SDK 和运维开发人员，涵盖新增能力、日常修改、部署和故障处理。

## 1. 新增工作流 / Skill

先判断新增需求的形态：相同流程内的材料或网格参数变化使用已有字段；新增静力、热等分析需要新模型和新工作流；新增载荷、局部赋材或预应力等业务语义需要扩展公开契约；若 Agent 需在中途观察后决策，则另行设计分阶段运行或工程会话。

新增分析按以下顺序完成：

1. 在 `app/schemas/` 定义明确的输入和结果模型，写清单位、选择范围、默认值和限制。
2. 在 `app/workflows/` 实现确定性步骤和结果语义核验，不通过 HTTP 调用自身。
3. 在 `app/workflows/registry.py` 注册 ID、版本、实现版本、步骤、模型、执行函数与验证函数。
4. 扩展公开 `AnalysisRequest`。有第二种公开流程时使用清晰的判别联合，确认 OpenAPI `oneOf` 与运行时验证一致。
5. 扩展 Worker 暂存、Runner 文件协议或结果交付机制，如新工作流确有多资产或多结果文件需求。
6. 编写参数、失败、幂等、执行和客户合同测试，生成 OpenAPI，更新对接和测试说明。

新增工作流不复制任务登记、幂等、领取、租约、取消和查询代码。它仍然需要独立的 Schema、业务实现、SDK 映射、结果校验和真实证据。

若未来接入 MCP，类型化工具例如 `submit_static_structural_analysis` 调用同一个业务服务；`get_analysis_run`、取消和结果查询仍可通用。MCP 需要单独实现工具发现、输入输出 Schema、身份与错误转换，REST operationId 不能直接当作 MCP 工具。

## 2. 常见修改定位

| 修改需求 | 首要位置 | 同步检查 |
| --- | --- | --- |
| 新字段、枚举、默认值 | `app/schemas/analysis.py` | 单位、业务语义、OpenAPI、示例 |
| 步骤顺序或中间 ID | `app/workflows/modal.py` | 注册步骤、失败处理、结果校验 |
| 工作流版本与能力描述 | `app/workflows/registry.py` | 实现是否存在、目录 / Schema 是否一致 |
| SDK 参数、中文枚举或单位 | `app/providers/jusmar/` | 真实证据与映射测试 |
| 资产、预检、提交或幂等 | `app/services/analysis_service.py` | 所属身份与输入快照 |
| 状态、领取、取消和租约 | `app/storage/jobs.py` | 事务、竞争和旧 Worker 写入 |
| 子进程、超时和回执 | `app/execution/worker.py`、`protocol.py` | 进程生命周期、版本和异常测试 |
| HTTP / 认证 | `app/api/` | 不将 HTTP 逻辑下沉到工作流 |
| 启动及容量参数 | `app/config.py`、`.env.example` | 本指南运行配置 |

内部 SDK 参数 `young_modulus` 若改名为 `elastic_modulus`，只改 Adapter 映射。若 SDK 改为 MPa，必须实现并验证 Pa → MPa 转换；不得保留 `_pa` 字段名后直接传同一数值。新增“面压力”则需要载荷类型、对象、数值、单位、方向和解析失败契约，现有布尔开关不具备这些含义。

## 3. 状态与数据维护规则

运行快照及索引状态只通过 `JobRepository` 的事务更新。完成写入校验尝试 ID、状态和未过期租约，旧 Worker 不得覆盖新状态。`unknown` 不自动改回 `queued`，因为外部 SDK 可能已经产生副作用。

当前数据库为版本 1。后续新建迁移脚本并添加显式升级逻辑；不要修改已交付的 `migrations/001_jobs.sql` 来升级已有数据库。升级前备份数据库、资产和作业文件，并验证历史快照能被读取。

文件系统和 SQLite 不是一个事务。上传先写文件再登记元数据，故障时可能存在未登记文件；运行结果依赖数据库和作业目录共同存在。不能通过递归删除 `.runtime` 处理异常。

## 4. 启动与配置

API 和 Worker 必须使用同一套配置、数据库、资产目录和作业目录：

```bash
.venv/bin/uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
.venv/bin/python -m app.execution.worker
```

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `CAE_PROVIDER` | `mock` | `jusmar` 当前会拒绝启动 |
| `CAE_DATABASE_PATH` | `.runtime/cae.db` | SQLite 元数据与作业队列 |
| `CAE_ASSET_ROOT` | `.runtime/assets` | 上传资产 |
| `CAE_JOB_ROOT` | `.runtime/jobs` | 每个任务的暂存、日志和结果 |
| `CAE_MAX_FILE_BYTES` | 10485760 | 上传 / 暂存文件限制 |
| `CAE_MAX_RECORDS` | 10000 | 资产与任务记录总上限 |
| `CAE_MAX_PROCESS_NUM` | 8 | 求解参数上限，不表示 GUI 并发 |
| `CAE_WORKER_LEASE_SECONDS` | 15 | 运行租约 |
| `CAE_RUN_TIMEOUT_SECONDS` | 300 | 当前 Mock 超时 |
| `CAE_ENABLE_LEGACY_API` | false | 内部原子接口回归开关 |

`/healthz` 只表示 API 存活。当前没有生产级 Worker、许可证或 GUI 就绪检查。

## 5. 故障处理与恢复

排队任务可由重启后的 Worker 领取。运行中 Worker 正常停止或异常终止时，保守进入 `unknown`；旧进程可能仍在运行，不能自动重放。`unknown` 会隔离执行槽位，先检查尝试目录中的 `process.json`、输入、进度、结果和日志，再确认 GUI / 求解器状态。

确认旧执行已经停止后，可解除隔离：

```bash
.venv/bin/python -m scripts.resolve_run \
  --run-id run_replace_me \
  --confirm-execution-stopped
```

该命令只将 `unknown` 记录为 `failed` 并释放槽位，不会停止外部进程、验证物理结果或自动重试。真实 GUI 模式还必须核对 GUI、Runner 和远程求解器。

单机 SQLite 不支持共享网络盘多机队列。真实生产部署需要集中数据库、资产分发、Worker 能力与桌面会话管理、许可证、正式身份认证、TLS、审计、备份和日志保留策略。

## 6. 开发校验

```bash
.venv/bin/ruff check app tests examples scripts
.venv/bin/pytest -q
.venv/bin/python -m scripts.export_openapi
.venv/bin/python -m scripts.check_docs
.venv/bin/python -m scripts.package_docs
```

不要手改 `docs/contracts/openapi.json` 或 `docs.zip`，它们都是生成物。发布新实现前处理仍绑定旧实现版本的排队任务；Worker 不会用新实现静默执行旧任务。
