# 开发与运维指南

## 环境和启动

见 [项目 README](../README.md)。Linux 使用 Python 3.10，开发验证为 3.10.11。虚拟环境用标准 `venv`，pip 显式使用官方源，不使用 uv。从项目根目录运行，相对路径按工作目录解析。

本地可直接 `python main.py` 启动 API，默认地址 `http://127.0.0.1:8000`，文档为 `/docs`。IDE 运行 main.py 时也应将工作目录设为项目根目录。首次启动前仍需手动 `python -m alembic upgrade head`；Worker 另开终端执行 `python worker.py`，不会由 main.py 自动拉起。

本地联调也可用仓库根目录的 `start.sh` 把两个终端合并为一条命令：`./start.sh start` 在后台按“迁移 → API → Worker”启动，`./start.sh stop` 先停 API 再停 Worker，`./start.sh status`、`./start.sh logs [api|worker]` 分别查看状态和日志。PID 与后台 stdout/stderr 在 `.runtime/`。只有当前没有服务运行时才会自动迁移；`--no-migrate` 跳过迁移，`migrate` 子命令在服务运行时会拒绝执行。该脚本只在 Linux/WSL 下可用，Worker 依赖 `fcntl`；容器部署不使用它。

运行依赖只有 10 项：FastAPI、fastapi-mcp、MCP Python SDK（`mcp`）、Pydantic、pydantic-settings、Uvicorn、SQLAlchemy、Alembic、Loguru、VTK。运行时和迁移都用 SQLAlchemy；底层使用标准库 sqlite3，不安装 aiosqlite。开发依赖分开；没有手动加入 Windows 专用包，传递依赖由 pip 按平台选择。

生产需要访问控制，配置工作目录权限、反向代理 TLS 和网络访问控制；服务自身不校验令牌。API 与 Worker 使用相同配置。启动顺序：手动迁移 → API → Worker。分别由进程管理器管理，不从 Web 启动钩子拉起 Worker。

## Docker Compose 部署步骤

仅支持同一 Linux 宿主机、本地文件系统上的一个 API + 一个 Worker。不是多节点部署方案。

### 1. 准备配置与目录

首次部署复制 `.env.example` 为 `.env`，把 `WORKSPACE` 改为宿主机上存放任务工作目录的绝对路径，把 `SSTA_CAE_PATH` 改为 CAE 安装目录的绝对路径，并按需填写 `CAE_GUIERUNNER_PATH`（受控启动器；留空则 Worker 无法执行任务）。不要覆盖已有 `.env`。Compose 固定容器内的数据库、工作目录和日志路径，`.env` 中的可变部分只用于宿主机挂载。

在部署项目根目录创建任务工作目录并确认运行账户可写：

```bash
mkdir -p workspace
docker compose config --quiet
```

`workspace` 会被挂载为容器内 `/opt/cae_service/workspace`，Compose 把 `CAE_DATABASE_PATH`、`CAE_WORKSPACE_ROOT`、`CAE_SERVICE_LOG_ROOT` 都指向它；`SSTA_CAE_PATH` 挂载为 `/opt/ssta-cae`。迁入已有数据库、日志或任务目录时，其权限也须逐项核对；不要盲目递归改权或使用 chmod 777。注意当前镜像以 root 运行，写回宿主机的文件属主是 root；若按合规要求改为非 root 运行，须给该账户对等权限并同步调整挂载目录属主。SELinux/rootless Docker 环境还需按平台配置访问权限。不要把 SQLite 放到 NFS/SMB。

### 2. 构建镜像

```bash
docker compose build
```

Dockerfile 以内部 `centos-conda:cos7-24.9.2-x86_64` 为基础镜像，复制仓库到 `/opt/cae_service`，pip 固定官方源安装 requirements。`.dockerignore` 排除 `.env`、数据库、日志、虚拟环境及开发测试文件。当前 Dockerfile 没有切换到非 root 用户；正式发布应补齐非 root 运行、把基础镜像替换为批准的镜像/digest并进行安全扫描。

内网无法下载时，在能访问官方源且与目标架构兼容的构建环境完成镜像构建，推送内网镜像仓库或通过 `docker save/load` 转运，不在容器启动时安装依赖。需要更换基础镜像时使用 `docker compose build --build-arg PYTHON_IMAGE=批准的镜像`；应用镜像名直接修改 `docker-compose.yaml` 中两处 image。

### 3. 手动迁移

```bash
docker compose run --rm --no-deps cae-run python -m alembic upgrade head
docker compose run --rm --no-deps cae-run python -m alembic current
```

这是临时管理容器，命令覆盖 API 默认启动命令，不启动常驻 API、Worker。失败时先排查，不继续启动。不要在镜像构建、entrypoint 或服务启动钩子中执行迁移。

### 4. 启动及检查

```bash
docker compose up -d cae-run worker
docker compose ps
docker compose logs -f cae-run worker
```

API 由 Compose 发布到宿主机 `0.0.0.0:8000`，需要限制来源时应改端口映射或用反向代理；Worker 无端口。简化配置不包含自动 healthcheck，可手动请求 `/healthz` 检查 API 存活；它不检查 Worker。Worker 启动失败通过容器退出/重启日志排查，不把 API 可访问当作流程可用证明。

调用方以 multipart 上传几何模型文件（例如 `part.stp`），不需要预先在容器内放置模型，也不需要挂载模型目录；服务把它写到 `/opt/cae_service/workspace/<run_id>/model/`，对应宿主机 `WORKSPACE/<run_id>/model/`。工程目录、日志和结果都由服务在同一任务目录下生成，API 和 Worker 都必须能访问该挂载点。CAE 安装目录由 `SSTA_CAE_PATH` 挂载为 `/opt/ssta-cae`，真实启动器需要它时应在 `CAE_GUIERUNNER_PATH` 中使用容器内路径。旧 queued 任务若保存了旧字段（例如 `project_dir`、`model_path`），执行前须人工核对，不自动补全。

### 5. 日志、停止与升级

日志同时输出到容器 stderr 和持久化文件；服务日志在宿主机 `WORKSPACE/logs`，任务日志和结果在 `WORKSPACE/<run_id>` 下。SQLite 也在同一挂载内，重建容器不会自动删除。

```bash
docker compose restart cae-run
docker compose stop worker
```

前者不停止 Worker；后者会向 Worker 发 SIGTERM，中断当前脚本、尽力记录 unknown，最多等待 45 秒再强制停止。整套 `docker compose down` 同样会停止执行，不是无损暂停。当前没有业务级排空接口，升级前暂停外部提交、等待 running 任务结束，再停服务、备份、迁移和启动。不要横向扩容 Worker。

Compose 没有设置 cae-run → worker 的 depends_on：两者都依赖已迁移数据库，但不互相依赖启动顺序。不会启动第三个数据库服务。

配置文件为 `docker-compose.yaml`，Docker Compose 可以自动发现，命令仍为 `docker compose ...`。文件直接列出两个服务，不使用 YAML 公共模板；采用短格式目录挂载，因此启动前务必检查模型路径已存在且拼写正确。非 root 用户由 Dockerfile 的 USER 指令指定，不在 Compose 重复声明。

### 6. 接入真实 guie2

镜像本身只负责调用外部受控启动器：Worker 执行 `CAE_GUIERUNNER_PATH` 加 `nogui` 与仓库内 `services/scripts/modal_nogui_process.py` 的路径。未配置 `CAE_GUIERUNNER_PATH` 时任务无法执行。接入真实环境需确认真实二进制的 Linux 依赖、图形/无界面模式、显示服务、GPU、许可证及前台退出行为，并确认脚本的退出码语义（当前脚本会捕获异常并以 0 退出）。不要以 privileged 或挂载 Docker socket 作为默认解决方案。GUI 依赖较大时可拆出专门 Worker 镜像，API 保持轻量。

## 修改位置

| 需求 | 修改位置 | 同步工作 |
| --- | --- | --- |
| 请求字段与校验 | `api/routes/` 中的 Form/File 声明 | 映射、测试、OpenAPI、对接指南 |
| 新增或修改 HTTP 接口 | `api/routes/`，在 `api/router.py` 注册 | schemas、契约、接口测试 |
| 环境变量名字/格式 | `services/modal.py` | 与受控脚本核对变量名、脚本契约测试 |
| 任务目录与结果路径 | `services/paths.py` | API/Worker 两侧一致、清理策略 |
| MCP 工具或 `/mcp` 访问控制 | `services/mcp_server.py`、`main.py` 的 lifespan | MCP 工具测试、Host 白名单 |
| 换真实启动命令 | `services/modal.py` 的 `command()` | 前台等待、GUI 会话、日志及超时验证 |
| 超时和子进程清理 | `services/executor.py` | 超时/取消测试 |
| 调度和恢复 | `worker.py` | 领取、锁、恢复测试 |
| 数据库结构 | `storage/models.py` | 生成并审查迁移、修改 repository |
| 连接、Session 或线程池边界 | `storage/database.py` | 线程隔离、事务取消和回滚测试 |
| 日志格式与保留 | `core/logging.py` | API/Worker 日志检查 |

接口模型不放 storage。存储层接收普通参数字典并返回数据库记录，HTTP 响应在 api 组装。简单功能不再增加 provider、registry、插件工厂等抽象。

repository 的 async 方法只把完整同步操作交给线程池。同步 helper 内用 `sessions.begin()` 管理写事务，`sessions()` 管理只读会话。不要把 Session 传回事件循环、跨线程使用，也不要在脚本运行时保留 Session。表结构不变的存储层重构无需创建迁移。

## Alembic：手动生成、手动执行

新环境执行已有迁移，不必重新 `alembic init` 或生成新基线：

```bash
python -m alembic upgrade head
python -m alembic current
python -m alembic check
```

后续先改 `storage/models.py`，在已升级到当前 head 的开发数据库上生成迁移，人工审查后提交：

```bash
python -m alembic revision --autogenerate -m "describe table change"
python -m alembic upgrade head
python -m alembic check
```

自动生成不能可靠推断重命名或数据转换，必须审查 upgrade/downgrade 并测试。发布时先停写和备份，再迁移、重启。当前使用 DELETE 日志模式；备份建议使用 SQLite backup 工具。历史 WAL 数据库不要只复制主 db 而遗漏未合并数据，也不要手动删除日志文件。

为适配当前 Navicat，`migrations/env.py` 在显式命令中设置并检查 `PRAGMA journal_mode=DELETE`，API/Worker 启动不会切换模式。部署升级前停止 API、Worker，断开 Navicat 等连接并备份，再运行既有 `alembic upgrade head`；即使已经是 head，也会执行日志模式配置。该命令同时会应用未执行的迁移，若只想转换旧文件而不迁移表，应另行在确认目标和备份后执行日志模式 PRAGMA。不要用新建空文件覆盖已有数据库。

`downgrade` 可能丢数据，初始版本降到 base 会删表，只用于隔离测试库或经批准的回滚。启动检查不会生成/应用迁移或清空旧库。不要对历史库直接 `stamp head` 假装结构已匹配。

## 新增流程

以静力分析为例：

1. 在 `services/scripts/` 放受控脚本，在 `services/modal.py` 定义命令与环境映射。
2. 在 `api/routes/` 增加提交路由（Form/File 声明请求字段）并注册到 `api/router.py`，复用任务状态、结果和日志接口；需要时同步 `services/mcp_server.py` 的 MCP 工具。
3. 当前 Worker 固定调用 modal。支持多流程时给任务表增加 `flow_type`，生成迁移并处理历史默认值。由路由写入流程类型，不接受任意脚本路径。
4. Worker 根据受控类型显式分支调用服务。少量流程无需插件系统。
5. 增加环境变量、成功/失败及结果测试，更新契约和文档。

相同流程新增参数通常无需新路由；虽然参数快照是 JSON，仍须处理已排队旧任务缺少新字段的情况。

## 日志与历史数据

- 任务：`<CAE_WORKSPACE_ROOT>/<run_id>/logs/stdout.log`、`logs/stderr.log`、`jusmar.log`、`cloud_info.json` 及云图 PNG。
- 上传的几何模型：`<CAE_WORKSPACE_ROOT>/<run_id>/model/<文件名>`。
- 工程：`<CAE_WORKSPACE_ROOT>/<run_id>/project`，由服务的 `services/paths.py` 统一创建，不支持调用方指定路径。
- 服务：`<CAE_SERVICE_LOG_ROOT>/api-YYYY-MM-DD.log`、`worker-YYYY-MM-DD.log`；Loguru 每日轮转，保留 30 天。

旧 uv 虚拟环境与缓存已移出项目；当前 `.venv` 是标准 venv 新建的验证环境，不提交 Git。部署应重新安装，不复制开发机虚拟环境。任务日志和工程不自动删除，须明确保留要求后清理。

## 契约与文档

```bash
python -m scripts.export_openapi
python -m scripts.check_docs
python -m scripts.package_docs
```

不手改生成的 OpenAPI JSON。`docs.zip` 可重复生成，不参与服务运行。

## 内网 Swagger

`/docs` 由 `api/routes/docs.py` 提供，JS、CSS、favicon 从本服务 `/static/docs/` 加载，OpenAPI 仍从本服务 `/openapi.json` 获取。Swagger 在线 validator 已禁用；不再提供默认依赖 CDN 的 `/redoc` 页面。服务不做鉴权，页面上没有可填写的凭据，也不使用 OAuth2 redirect 页面。

`static/docs/` 内固定保存官方 `swagger-ui-dist` 5.33.0 的发布文件、LICENSE、NOTICE、第三方依赖许可证和 `manifest.json`。manifest 记录发布包来源、完整性值及各文件 SHA-256；升级资源时在外网下载固定版本、核对完整性、同步更新 manifest 并跑测试，不在服务启动时下载。此目录必须提交 Git 并随镜像 COPY，不能当缓存删除；不是 Python 或 npm 运行依赖。

仅挂载 `/static/docs`，不把整个 static 公开；任务日志通过接口读取。Compose 不挂载 `static/`，镜像内的 `static/docs` 不会被覆盖。反向代理添加路径前缀时正确配置 Uvicorn `--root-path`，资源和 OpenAPI 地址会使用该前缀。

离线验收：浏览器断开外网但保持内网服务可达，打开 `/docs`，在 Network 中确认 JS/CSS/图标/OpenAPI 均来自本服务，并直接调用查询接口验证。后端自动测试覆盖页面本地地址、静态资源读取、前缀、关闭 ReDoc 和日志目录隔离，不替代真实浏览器与反向代理验收。

## MCP 接口

`main.py` 启动时按 `CAE_MCP_ENABLED` 决定是否把 MCP 子应用挂到 `/mcp`；MCP 依赖不可用时只记录错误并跳过挂载，REST 接口照常提供。`app.mount()` 不会运行子应用 lifespan，所以 session manager 由 lifespan 中的独立任务启动和停止。

- `CAE_PUBLIC_BASE_URL` 决定 `get_run_result` 返回的 `image_url` 前缀，必须是调用方能访问到的地址；部署后不要保留默认的 `http://0.0.0.0:8000`。
- `CAE_MCP_ALLOWED_HOSTS` 是逗号分隔的额外 Host 白名单（支持 `:*` 通配端口）。MCP 传输层默认只接受本机 Host，其他 Host 返回 421；用域名或内网地址访问 `/mcp` 时，该地址必须出现在 `CAE_PUBLIC_BASE_URL` 或这个变量中。值为 `*` 会关闭校验，只建议在内网自有网络使用。
- `/mcp` 与 REST 共用同一数据库、任务目录和 Worker，但不出现在 `/openapi.json` 里；健康检查仍只看 `/healthz`。
