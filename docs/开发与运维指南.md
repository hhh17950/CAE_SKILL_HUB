# 开发与运维指南

## 环境和启动

见 [项目 README](../README.md)。Linux 使用 Python 3.10，开发验证为 3.10.11。虚拟环境用标准 `venv`，pip 显式使用官方源，不使用 uv。从项目根目录运行，相对路径按工作目录解析。

本地可直接 `python main.py` 启动 API，默认地址 `http://127.0.0.1:8000`，文档为 `/docs`。IDE 运行 main.py 时也应将工作目录设为项目根目录。首次启动前仍需手动 `python -m alembic upgrade head`；Worker 另开终端执行 `python worker.py`，不会由 main.py 自动拉起。

运行依赖只有 7 项：FastAPI、Pydantic、pydantic-settings、Uvicorn、SQLAlchemy、Alembic、Loguru。运行时和迁移都用 SQLAlchemy；底层使用标准库 sqlite3，不安装 aiosqlite。开发依赖分开；没有手动加入 Windows 专用包，传递依赖由 pip 按平台选择。

生产替换 token，配置模型目录权限、反向代理 TLS 和网络访问控制。API 与 Worker 使用相同配置。启动顺序：手动迁移 → API → Worker。分别由进程管理器管理，不从 Web 启动钩子拉起 Worker。

## Docker Compose 部署步骤

仅支持同一 Linux 宿主机、本地文件系统上的一个 API + 一个 Worker。不是多节点部署方案。

### 1. 准备配置与目录

首次部署复制 `.env.example` 为 `.env`，修改 `CAE_API_TOKENS`，将 `MODEL_HOST_DIR` 改为已有的模型目录绝对路径。不要覆盖已有 `.env`。Compose 固定容器内数据库和输出路径，`.env` 的对应本机路径只供本地开发使用。

在部署项目根目录创建数据目录并给容器 UID/GID 10001 写权限：

```bash
mkdir -p workspace static/logs
sudo chown 10001:10001 ./workspace ./static/logs
sudo chmod 0770 ./workspace ./static/logs
docker compose config --quiet
```

以上权限命令针对新部署的两个目录。如果迁入已有数据库、日志或工程，其文件权限也须逐项核对；不要盲目递归改权或使用 chmod 777。模型目录须允许 UID 10001 遍历、读取；容器内按只读挂载。SELinux/rootless Docker 环境还需按平台配置访问权限。不要把 SQLite 放到 NFS/SMB。

### 2. 构建镜像

```bash
docker compose build
```

Dockerfile 默认 `python:3.10.11-slim-bullseye`，仅安装运行 requirements，pip 固定官方源。`.dockerignore` 与显式 COPY 排除 `.env`、数据库、日志、模型、虚拟环境及开发测试文件。正式发布应将基础镜像替换为批准的镜像/digest并进行安全扫描，历史 3.10.11 基线不等于最新安全补丁。

内网无法下载时，在能访问官方源且与目标架构兼容的构建环境完成镜像构建，推送内网镜像仓库或通过 `docker save/load` 转运，不在容器启动时安装依赖。需要更换基础镜像时使用 `docker compose build --build-arg PYTHON_IMAGE=批准的镜像`；应用镜像名直接修改 `docker-compose.yaml` 中两处 image。

### 3. 手动迁移

```bash
docker compose run --rm --no-deps api python -m alembic upgrade head
docker compose run --rm --no-deps api python -m alembic current
```

这是临时管理容器，命令覆盖 API 默认启动命令，不启动常驻 API、Worker。失败时先排查，不继续启动。不要在镜像构建、entrypoint 或服务启动钩子中执行迁移。

### 4. 启动及检查

```bash
docker compose up -d api worker
docker compose ps
docker compose logs -f api worker
```

API 默认宿主机地址为 `127.0.0.1:8000`，远端调用通过反向代理；Worker 无端口。简化配置不包含自动 healthcheck，可手动请求 `/healthz` 检查 API 存活；它不检查 Worker。Worker 启动失败通过容器退出/重启日志排查，不把 API 可访问当作流程可用证明。

调用方填写 `/models/part.stp`，该文件对应宿主机 `MODEL_HOST_DIR/part.stp`。两个容器看到的模型路径必须一致。原来保存宿主机绝对路径的旧 queued 任务不能直接在容器里执行，应先核对和处理，不自动修改历史参数。

### 5. 日志、停止与升级

日志同时输出到容器 stderr 和持久化文件；任务日志仍在宿主机 `static/logs`，服务日志在 `workspace/logs`。SQLite 和工程也在 bind mount 内，重建容器不会自动删除。

```bash
docker compose restart api
docker compose stop worker
```

前者不停止 Worker；后者会向 Worker 发 SIGTERM，中断当前脚本、尽力记录 unknown，最多等待 45 秒再强制停止。整套 `docker compose down` 同样会停止执行，不是无损暂停。当前没有业务级排空接口，升级前暂停外部提交、等待 running 任务结束，再停服务、备份、迁移和启动。不要横向扩容 Worker。

Compose 没有设置 api → worker 的 depends_on：两者都依赖已迁移数据库，但不互相依赖启动顺序。不会启动第三个数据库服务。

配置文件为 `docker-compose.yaml`，Docker Compose 可以自动发现，命令仍为 `docker compose ...`。文件直接列出两个服务，不使用 YAML 公共模板；采用短格式目录挂载，因此启动前务必检查模型路径已存在且拼写正确。非 root 用户由 Dockerfile 的 USER 指令指定，不在 Compose 重复声明。

### 6. 接入真实 guie2

当前镜像只能执行测试脚本。需确认真实二进制的 Linux 依赖、图形/无界面模式、显示服务、GPU、许可证及前台退出行为。不要以 privileged 或挂载 Docker socket 作为默认解决方案。GUI 依赖较大时可拆出专门 Worker 镜像，API 保持轻量。

## 修改位置

| 需求 | 修改位置 | 同步工作 |
| --- | --- | --- |
| 请求字段与校验 | `api/schemas.py` | 映射、测试、OpenAPI、对接指南 |
| 新增或修改 HTTP 接口 | `api/routes/`，在 `api/router.py` 注册 | schemas、契约、接口测试 |
| 环境变量名字/格式 | `services/modal.py` | 脚本契约测试 |
| 换真实启动命令 | `services/modal.py` 的 `command()` | 前台等待、GUI 会话、日志及超时验证 |
| 超时和子进程清理 | `services/executor.py` | 超时/取消测试 |
| 调度和恢复 | `worker.py` | 领取、锁、恢复测试 |
| 数据库结构 | `storage/models.py` | 生成并审查迁移、修改 repository |
| 连接、Session 或线程池边界 | `storage/database.py` | 线程隔离、事务取消和回滚测试 |
| 日志格式与保留 | `core/logging.py` | API/Worker 日志检查 |

接口模型不放 storage。存储层接收普通参数字典并返回数据库记录，HTTP 响应在 api 组装。简单功能不再增加 provider、registry、插件工厂等抽象。

repository 的 async 方法只把完整同步操作交给线程池。同步 helper 内用 `sessions.begin()` 管理写事务，`sessions()` 管理只读会话。不要把 Session 传回事件循环、跨线程使用，也不要在脚本运行时保留 Session。表结构不变的存储层重构无需创建迁移。

## Alembic：手动生成、手动执行

新环境执行已有迁移，不必重新 `alembic init` 或生成新基线：

```bash
python -m alembic upgrade head
python -m alembic current
python -m alembic check
```

后续先改 `storage/models.py`，在已升级到当前 head 的开发数据库上生成迁移，人工审查后提交：

```bash
python -m alembic revision --autogenerate -m "describe table change"
python -m alembic upgrade head
python -m alembic check
```

自动生成不能可靠推断重命名或数据转换，必须审查 upgrade/downgrade 并测试。发布时先停写和备份，再迁移、重启。当前使用 DELETE 日志模式；备份建议使用 SQLite backup 工具。历史 WAL 数据库不要只复制主 db 而遗漏未合并数据，也不要手动删除日志文件。

为适配当前 Navicat，`migrations/env.py` 在显式命令中设置并检查 `PRAGMA journal_mode=DELETE`，API/Worker 启动不会切换模式。部署升级前停止 API、Worker，断开 Navicat 等连接并备份，再运行既有 `alembic upgrade head`；即使已经是 head，也会执行日志模式配置。该命令同时会应用未执行的迁移，若只想转换旧文件而不迁移表，应另行在确认目标和备份后执行日志模式 PRAGMA。不要用新建空文件覆盖已有数据库。

`downgrade` 可能丢数据，初始版本降到 base 会删表，只用于隔离测试库或经批准的回滚。启动检查不会生成/应用迁移或清空旧库。不要对历史库直接 `stamp head` 假装结构已匹配。

## 新增流程

以静力分析为例：

1. 在 `services/scripts/` 放受控脚本，在 `services/static_analysis.py` 定义命令与环境映射。
2. 在 `api/schemas.py` 定义请求，在 `api/routes/` 增加提交路由并注册到 `api/router.py`，复用任务状态和日志接口。
3. 当前 Worker 固定调用 modal。支持多流程时给任务表增加 `flow_type`，生成迁移并处理历史默认值。由路由写入流程类型，不接受任意脚本路径。
4. Worker 根据受控类型显式分支调用服务。少量流程无需插件系统。
5. 增加环境变量、成功/失败及结果测试，更新契约和文档。

相同流程新增参数通常无需新路由；虽然参数快照是 JSON，仍须处理已排队旧任务缺少新字段的情况。

## 日志与历史数据

- 任务：`static/logs/<run_id>/stdout.log`、`stderr.log`、`jusmar.log`。
- 工程/结果：`workspace/runs/<run_id>/project/`、`cloud_info.json`。
- 服务：`workspace/logs/api-YYYY-MM-DD.log`、`worker-YYYY-MM-DD.log`；Loguru 每日轮转，保留 30 天。
- 历史库：`workspace/archive/runtime-before-refactor-20260921/cae.db`，不参与当前运行。

旧 uv 虚拟环境与缓存已移出项目；当前 `.venv` 是标准 venv 新建的验证环境，不提交 Git。部署应重新安装，不复制开发机虚拟环境。任务日志和工程不自动删除，须明确保留要求后清理。

## 契约与文档

```bash
python -m scripts.export_openapi
python -m scripts.check_docs
python -m scripts.package_docs
```

不手改生成的 OpenAPI JSON。`docs.zip` 可重复生成，不参与服务运行。

## 内网 Swagger

`/docs` 由 `api/routes/docs.py` 提供，JS、CSS、favicon 从本服务 `/static/docs/` 加载，OpenAPI 仍从本服务 `/openapi.json` 获取。Swagger 在线 validator 已禁用；不再提供默认依赖 CDN 的 `/redoc` 页面。当前使用 HTTP Bearer，不需要 OAuth2 redirect 页面。

`static/docs/` 内固定保存官方 `swagger-ui-dist` 5.33.0 的发布文件、LICENSE、NOTICE、第三方依赖许可证和 `manifest.json`。manifest 记录发布包来源、完整性值及各文件 SHA-256；升级资源时在外网下载固定版本、核对完整性、同步更新 manifest 并跑测试，不在服务启动时下载。此目录必须提交 Git 并随镜像 COPY，不能当缓存删除；不是 Python 或 npm 运行依赖。

仅挂载 `/static/docs`，不把整个 static 公开；`static/logs` 依然需要通过鉴权日志接口访问。Compose 只挂载 static/logs，不覆盖镜像中的 static/docs。反向代理添加路径前缀时正确配置 Uvicorn `--root-path`，资源和 OpenAPI 地址会使用该前缀。

离线验收：浏览器断开外网但保持内网服务可达，打开 `/docs`，在 Network 中确认 JS/CSS/图标/OpenAPI 均来自本服务；Authorize 后尝试查询接口。后端自动测试覆盖页面本地地址、静态资源读取、前缀、关闭 ReDoc 和日志目录隔离，不替代真实浏览器与反向代理验收。
