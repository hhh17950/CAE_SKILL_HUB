# 测试与交付指南

本指南说明当前验证覆盖、验收命令、Mock 边界和真实接入前仍缺少的证据。

## 1. 当前已验证的范围

| 层次 | 已验证内容 |
| --- | --- |
| 参数与合同 | 未知字段、枚举、显式单位 / 物性、OpenAPI |
| 资产与归属 | 上传、身份隔离、SHA-256、执行前文件一致性 |
| 持久任务 | 重启恢复、幂等、并发领取、租约和旧 Worker 写入隔离 |
| 执行边界 | 独立 Mock 子进程、步骤回传、取消、超时和求解失败 |
| 结果交付 | 输入、尝试、版本及结果文件完整性校验 |
| 客户视角 | 纯 HTTP 上传、预检、提交、查询、结果和下载 |
| 文档 | 本地链接、JSON 示例、路由表与导出 OpenAPI 一致性 |

本次基线已通过 54 项自动测试。独立 API、Worker 和 Mock 入口进程的本机 HTTP 验收也已通过，验证 API 重启后仍可读取任务结果和文件。机器可读记录见 [验收报告](./contracts/acceptance-report.json)。

## 2. 执行测试

```bash
.venv/bin/ruff check app tests examples scripts
.venv/bin/pytest -q
.venv/bin/python -m scripts.export_openapi --check
.venv/bin/python -m scripts.check_docs
```

进行端到端 Mock 验收时，先启动 API 和 Worker，再运行：

```bash
.venv/bin/python -m examples.modal_workflow
```

预期 `passed: true`，并验证幂等重放、11 步执行、Mock 标记、输入摘要、结果文件摘要和材料引用。

也可让脚本自动启停临时 API 与 Worker，并检查 API 重启恢复：

```bash
.venv/bin/python -m scripts.acceptance_workflow \
  --report docs/contracts/acceptance-report.json
```

该命令需要运行环境允许监听本机端口；报告只代表生成时的代码版本，修改代码后需重新执行。

## 3. 关键失败验收

- 传 `fixed` 边界、`loads` 或未支持字段：422，不创建运行。
- 缺少材料物性或几何单位：422，不偷偷采用 SDK 默认值。
- 同键并发提交相同请求：只创建一个运行；同键不同请求：409。
- 提交求解成功但求解失败：运行 `failed`，不生成成功结果。
- 排队取消：不启动执行；运行中取消：确认 Mock 进程停止后进入 `cancelled`。
- 租约过期：进入 `unknown`，禁止旧 Worker 写入和自动重放。
- 资产、回执身份、退出码或结果文件不一致：不能发布为成功结果。

## 4. Mock 的边界

Mock 可以证明协议、输入快照、身份归属、任务状态、步骤顺序和进程回执闭环。它不能证明 CAD 有效、单位真实转换、网格质量、边界条件、刚体模态、求解精度、真实 GUI 焦点 / 许可证或工程恢复。

Mock 结果不产生貌似真实的频率、位移或应力。测试夹具是文本文件，不能作为真实 CAD 验收样本。

## 5. 真实交付前的验收

真实 SDK 接入后，CAE 专家应提供受控工程与基准结果，明确单位、边界、材料、求解设置、允许误差、归一化与输出格式。至少完成一条完整真实流程、一次回执中断后的状态核对、一次取消或超时清理、一个可解释的真实错误，以及第二种真实分析流程的扩展验证。

当前未交付：真实 `jusmar_app` / GUI Runner、真实物理结果、MCP 服务端、多机调度、正式身份系统、高可用和真实 SDK 断点恢复。真实模式保持拒绝启动，避免 Mock 成功被误解为真实 CAE 可用。

接口、实现与文档更新后重新导出 OpenAPI 和文档包：

```bash

.venv/bin/python -m scripts.package_docs
```
