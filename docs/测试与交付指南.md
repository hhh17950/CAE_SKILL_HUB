# 测试与交付指南

## 自动化测试

在项目根目录的 Python 3.10 虚拟环境执行：

```bash
PIP_CONFIG_FILE=/dev/null python -m pip --isolated install --index-url https://pypi.org/simple -r requirements-dev.txt
python -m pip check
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
python -m scripts.export_openapi --check
python -m scripts.check_docs
```

快速测试将等待缩短到 0.01 秒，但启动真实 Python 子进程，不仅 mock 返回值。每项测试使用临时数据库，通过 Alembic CLI 先迁移；应用自身不迁移。

覆盖：multipart 上传与字节保真、环境变量映射、退出码、超时、取消、参数校验、任务目录隔离、三类日志、缺失/损坏结果、数据库版本检查、显式迁移/回滚、重启恢复、单 Worker 锁、MCP 工具与传输层 Host 校验、离线 Swagger 资源与校验和、文档与契约一致性。

`tests/test_runs.py`、`tests/test_storage.py`、`tests/test_deployment.py` 已按当前实现重写：multipart 上传、请求体里没有 owner 维度、服务自身不做 Bearer 鉴权、任务目录由 `CAE_WORKSPACE_ROOT` 决定。真正执行流程脚本的用例依赖 POSIX（`fcntl`、进程组），在 Windows 上明确跳过，交付前须在 Linux 上跑一遍。

本轮在 Python 3.10.11 下移除 aiosqlite 后验证 SQLAlchemy 存储、线程隔离、事务取消等待、原子领取与回滚。新增 Compose 配置检查和离线 Swagger 资源、校验和、反向代理前缀、日志隔离测试。Compose 配置测试不需要 Docker 引擎；缺少 Docker CLI/Compose 时会明确跳过。

## 实际 60 秒验收

```bash
CAE_RUN_SLOW_TESTS=1 python -m pytest -q tests/test_runs.py -k sixty
```

保留实际 60 秒等待，期间检查 API 可响应、任务为 running，结束后为 succeeded。默认快速测试跳过此项；该用例依赖 POSIX，Windows 上被跳过，没有 Linux 环境时可用下文的人工验收替代。

人工按 [对接指南](对接指南.md) 上传几何模型提交任务，检查 `<CAE_WORKSPACE_ROOT>/<run_id>` 下的 `model/`、`project/`、`logs/stdout.log`、`logs/stderr.log`、`jusmar.log` 和 `cloud_info.json` 是否按预期生成，并确认云图接口能取到图。把 `CAE_RUN_TIMEOUT_SECONDS` 设为 1 再提交长任务可验证 `timed_out`；把 `CAE_CLOUD_TIMEOUT_SECONDS` 设为 1 可验证云图渲染超时被判为 `failed`（`error` 写明超时）而不是一直 `running`；验收后恢复默认配置。测试环境暂时没有可执行流程时，可用 `python -m services.scripts.simulate_cloud_run --modes 3` 造一个已完成任务，验证结果接口、云图下载接口以及智能体取图链路（模拟数据，不是仿真结果）。

## Linux 与真实系统验收

开发主机为 Windows（Python 3.10.11）；实现面向 Linux/POSIX，使用 `fcntl.flock`、进程组和信号，不提供 Windows 分支。因此 `worker.py` 及其相关用例无法在 Windows 上导入和运行，Windows 只能验证 API 侧；本机 Docker 未运行，不能将开发机测试当作已完成 Linux 验收。内网 Linux 交付前须重复安装、迁移、快速测试和超时验收，验证进程管理器的停止清理。

双容器检查：按开发指南构建、手动迁移、启动，上传一个小几何模型提交；执行中 `docker compose restart cae-run` 后应能继续查询原任务，Worker 不被重启。检查任务目录挂载权限、日志持久化、Worker 停止后的 unknown 状态。数据库应为 DELETE 日志模式，Navicat 查看前确认文件及父目录权限，不删除辅助文件。自动测试验证 DELETE 模式下的完整性与并发领取。

离线 Swagger 检查：断开外网后打开 `/docs`，页面资源和 OpenAPI 应来自同一内网服务。自动测试验证 HTTP 资源地址及文件完整性；实际浏览器渲染、反向代理与容器镜像启动仍需部署环境验收。

真实 guie2 另行验收：`CAE_GUIERUNNER_PATH` 启动命令、8 个环境变量、数值单位、GUI 会话和许可证、前台等待、日志编码、结果 JSON 及进程树清理。当前流程脚本会捕获异常并固定以 0 退出，所以退出码 0 不能当作流程成功，必须同时检查 `cloud_info.json` 和云图。本服务不能验证 CAD、网格、材料语义或求解正确性。

## 交付清单

- 一起交付运行代码、requirements、迁移、Dockerfile、docker-compose.yaml、测试、当前 docs 和 static/docs 离线资源及许可证。
- 不交付 `.venv`、缓存、`.env` 密钥、历史库、客户模型和运行日志。
- 当前无多机 Worker、HTTP 取消、自动重试，服务自身也没有鉴权；几何模型上传和 MCP Server 已实现，用法见 [对接指南](对接指南.md)，交付说明不应否认也不应夸大。
- 部署方需明确访问控制（反向代理或网络策略）、日志保留、磁盘配额和备份恢复策略。
